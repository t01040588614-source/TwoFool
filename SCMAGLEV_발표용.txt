■ 1. 한 줄 소개 (30초)
--------------------------------------------------------------------------------
"SCMAGLEV는 승객 예매부터 실시간 관제, GPT 기반 운영 보조까지 하나로 연결한
 통합 철도 플랫폼입니다. 승객은 앱처럼 열차를 검색·예매하고, 관제사는
 대시보드에서 전국 열차를 모니터링하며 AI로 안내문·인수인계를 생성합니다."


■ 2. 프로젝트 목적
--------------------------------------------------------------------------------
- 승객용 예매 서비스 + 운영 관제 대시보드를 단일 백엔드로 통합
- 전국 노선·역·편성 데이터 기반 실시간 운행 시뮬레이션
- ML/DL 혼잡 예측 + OpenAI GPT 추천·운영 문구 생성
- 예매/결제/취소/운영 로그(ACK)/고장 복구 등 실무형 워크플로우 구현


■ 3. 기술 스택
--------------------------------------------------------------------------------
[백엔드]
  Flask, SQLAlchemy, Flask-JWT-Extended, Flask-SocketIO
  SQLite (개발), Python 3.x

[프론트]
  Jinja2 템플릿, HTML/CSS/Vanilla JavaScript
  Leaflet 지도 + MarkerCluster (427대 열차 클러스터링)

[AI/ML]
  ml_predictor.py — ML/DL 혼잡도 예측·Ensemble
  openai_recommender.py — 승객 GPT 추천 문구
  openai_dashboard.py — 관제 GPT 초안(안내문·인수인계·교대·권장조치)

[결제]
  TossPayments 테스트 연동 (키 없으면 모의 결제)

[테스트]
  Pytest (예매·관제·AI draft·ACK 등)


■ 4. 실행 방법 (발표 전 체크리스트)
--------------------------------------------------------------------------------
1) 폴더 이동
   cd "c:\02.복습\백엔드 프로젝트 파일"

2) 의존성 (최초 1회)
   pip install -r requirements.txt

3) .env 필수 설정
   JWT_SECRET_KEY=임의의_긴_비밀값

   [선택 — GPT 데모]
   OPENAI_API_KEY=sk-...
   OPENAI_MODEL=gpt-4o-mini
   OPENAI_ENABLED=auto

   [선택 — 토스 결제창]
   TOSS_PAYMENTS_CLIENT_KEY=test_ck_...
   TOSS_PAYMENTS_SECRET_KEY=test_sk_...
   TOSS_PAYMENTS_MOCK_ONLY=0

4) 서버 실행
   run_server.bat  또는  python app.py

5) 접속 URL
   승객 서비스  : http://127.0.0.1:5001/
   관제 대시보드 : http://127.0.0.1:5001/dashboard
   헬스체크     : http://127.0.0.1:5001/api/health

※ OpenAI Key 넣은 뒤에는 서버 재시작 필수
※ Key 없어도 규칙 기반 fallback으로 전 기능 동작

■ 7. GPT / AI 연동 (핵심 차별점)
--------------------------------------------------------------------------------

[연동 상태 표시]
  대시보드 헤더 배지
  - "GPT · gpt-4o-mini" → Key 설정·정상
  - "규칙 기반" → Key 미설정
  - "GPT · 비활성" → Key 있으나 OPENAI_ENABLED=0

[승객 페이지]
  API : GET /api/scmaglev/passenger/recommendations
  - ai_source: "openai" 이면 「GPT 추천」 표시
  - fastest / cheapest / comfortable 3카드 reason_line GPT 보강
  - 실패 시 규칙 기반 fallback

  API : POST /api/scmaglev/ai/chat
  - 자연어 질문 → route_hint(출발/도착)로 검색 폼·AI 추천 자동 갱신

  public-summary.passenger_notices
  - 관제 PASSENGER_NOTICE_DELAY / RECOVERY / EMERGENCY_BROADCAST 반영
  - 승객 공지 배너 + 우하단 토스트 + 운행정보 탭 목록

[관제 대시보드]
  API : POST /api/scmaglev/dashboard/ai/draft

  draft_type          | 용도
  --------------------|------------------------------------------
  handover            | AI 인수인계 메모
  delay_notice        | 지연 승객 안내문
  recovery_notice     | 복구 승객 안내문
  shift_report        | AI 교대 리포트
  broadcast           | 긴급 방송 초안
  incident_actions    | 이벤트 선택 시 권장 조치 3줄

  UI 버튼
  - ✨ AI 인수인계 / ✨ AI 안내문
  - ✨ AI 지연안내 발송 / ✨ AI 복구안내 발송  ← GPT 작성 후 운영 로그 기록
  - ✨ AI 리포트 (교대)
  - ✨ 다시 생성 (이슈 권장 조치)

[승객 앱 연동 신뢰도 — passenger_trust]
  - 지연 위험도 LOW/MEDIUM/HIGH
  - 네트워크 정상률 · 예측 정확도
  - 승객 페이지와 동일 summary API 공유


■ 8. 관제 운영 기능
--------------------------------------------------------------------------------
- 실시간 열차 위치 시뮬레이션 (Socket.IO + 3~5초 폴링)
- 운행 상태 : normal / delayed / stopped / disrupted / arrived
- 고장 시뮬레이션 (11종 고장 코드) + 수동/자동 복구
- OperationEventLog : 알람·운영액션·결제·차량고장 이벤트
- ACK 단건 / 미확인 전체 ACK (controller·admin 권한)
- 운영 액션 기록 (POST /api/scmaglev/dashboard/actions)
    EMERGENCY_BROADCAST, SPEED_LIMIT_ADVISORY, SPARE_TRAIN_DEPLOYMENT,
    PASSENGER_NOTICE_DELAY, PASSENGER_NOTICE_RECOVERY, INCIDENT_FOCUS 등
- build_dashboard_summary() → alarms[], fault_trains[], prediction_summary, passenger_notices[]


■ 9. 승객 예매 흐름
--------------------------------------------------------------------------------
1. 출발/도착역 입력 → 열차 검색
2. AI 추천 카드 또는 목록에서 편성 선택
3. 좌석 선택 → 예약 생성 (pending_payment)
4. Toss 결제 prepare → confirm (또는 모의 결제)
5. 예약 조회 · 여정 확인 · 취소

■ 15. Q&A 예상 답변
--------------------------------------------------------------------------------
Q. GPT 없이도 되나요?
A. 네. 규칙 기반 템플릿으로 추천·안내문·권장조치 모두 동작합니다.

Q. 실시간 데이터는 진짜인가요?
A. 시뮬레이션입니다. DB 편성·스케줄 기반으로 위치·상태·고장을 주기 갱신합니다.

Q. 승객과 관제는 어떻게 연결되나요?
A. public-summary의 passenger_trust가 승객 UI·관제 UI에 공통 표시됩니다.

Q. 보안은?
A. JWT·역할 기반(controller/admin). 발표용 계정은 .env로 변경 가능.
   화면/HTML에는 비밀번호를 노출하지 않습니다.

Q. 확장 계획?
A. DB를 PostgreSQL로, 실제 신호 데이터 연동, GPT 안내문 SMS/푸시 연동 등.
